# DeepSeek Time Watcher · 峰谷时段小助手

一个轻量的**纯本地网页**,实时显示 DeepSeek API 当前处于峰时还是谷时、全天 24 小时峰谷分布圆环,以及距离下一次峰谷切换的倒计时。

- 无需服务器、数据库、API Key、账号登录或任何付费服务
- 无框架、无构建工具、无 CDN、无在线字体/图片,原生 HTML + CSS + JavaScript
- 双击 `index.html` 即可使用(支持 macOS 常见浏览器通过 `file://` 直接打开)

## 日期判定优先级

`schedule.js` 中的 `resolveDateType()` 按以下顺序判定,**手动修正 > 法定节假日 > 周末 > 工作日**:

1. **手动日期修正**(最高优先级)
   - `holiday`:标记为节假日 → 全天谷时;
   - `normal`:标记为普通计费日 → 忽略自动节假日标记,再按星期与时段判断。
2. **自动法定节假日**(命中 `config.js` 的 `holidays` 列表)→ 全天谷时。
3. **周六 / 周日** → 全天谷时。
4. **普通工作日** → 按峰时区间表判断。

注意:**"普通计费日"不会把周末变成峰时日**。例如周六被标记为 `normal`(模拟调休上班),
星期判断仍然生效,该周六依旧全天谷时——DeepSeek 按自然星期计费,与调休无关。

## 时区设计

- **计费判断基准时区固定为 `Asia/Shanghai`(北京时间,UTC+8,无夏令时)**,不可更改。
- 显示时区两个选项:**北京时间**(默认)/ **系统本地时间**。
  系统本地时区通过 `Intl.DateTimeFormat().resolvedOptions().timeZone` 获取。
- **时区切换只改变数字时钟的显示,不改变任何峰谷判断**:
  - 峰谷状态仍按北京时间计算;
  - 圆环始终表示北京时间当天 00:00–24:00;
  - 当前时刻标记按北京时间定位;
  - 倒计时按真实的下一次北京时间切换时刻计算。
- 界面会明确提示当前显示时区、计费时区,并展示"当地时刻 · 北京时刻"的对应关系。
- 时区转换**不使用固定小时偏移**,而是通过 `Intl.DateTimeFormat.formatToParts()`
  与迭代校正的显式转换函数 `zonedTimeToUtc()` 完成,因此系统本地时区涉及夏令时
  (如 `America/New_York`)也正确;夏令时跳空(不存在的时刻)会抛出明确错误。

## 24 小时圆环说明

圆环是本项目的核心可视化,使用 **SVG 动态绘制**(非静态图片):

- **00:00 位于正上方**,时间顺时针递增:06:00 在右、12:00 在下、18:00 在左,24:00 与 00:00 重合。
- 角度换算:`角度 = 当天分钟数 / 1440 × 360 - 90`(减 90° 使 00:00 朝上)。
- 每个真实区间**分别绘制**一段圆弧:峰时蓝色 `#4D8CFF`,谷时白色 `#FFFFFF`,
  圆环底座为深蓝色,确保白色弧线清晰;普通工作日共 5 段,周末/节假日为完整白色圆环。
- 全天区间保证**无重叠、无遗漏、合计 1440 分钟**(有对应单元测试)。
- **当前时刻标记**:独立的琥珀金圆点 + 短针,按北京时间当天秒数旋转(只转标记组,
  绝不旋转整条圆环),带柔和脉动发光,与蓝白弧线属于不同视觉层级。
- 辅助信息:每小时细刻度、00/06/12/18 数字标签、图例(蓝=峰时,白=谷时,金=当前时刻)。
- 只有**日期变化、规则修正变化或强制刷新**时才重绘弧线;每秒仅更新时钟文字、
  倒计时文字与标记角度,不做整页重建。

## 倒计时语义

- 显示 `距离下一次峰谷切换:HH:MM:SS`(超过 24 小时时带"X 天")。
- 由统一规则函数 `getNextSwitch()` 计算:从当前时刻逐日扫描段边界,找到第一个
  "左右状态不同"的边界,**不假设切换一定发生在当天**:
  - 工作日 18:00 后 → 次日(或下一个工作日)09:00;
  - 周五 18:00 后 → 跳过整个周末到周一 09:00;
  - 节假日前夕 → 跨过整个假期。
- 全天谷时的日期显示"**今日无峰时 · 全天谷时**",并额外给出
  "**下一峰时预计于 M 月 d 日(周 X)HH:mm 开始**"及距离时长。
- 倒计时向上取整到秒(边界处显示 1 秒而非 0),到达边界立即刷新状态,不出现负数。
- 页面从后台切回前台(`visibilitychange`)时立即全量重算,避免时钟/倒计时漂移。

## 节假日与日期修正

### 界面管理(推荐)

点击角色卡片打开设置面板 →「节假日 / 日期修正管理」:

- 查看已收录的法定节假日(灰色为已过去日期)与收录范围说明;
- 添加修正:选择日期 + 类型(节假日 / 普通计费日);
- 删除单条修正,或"恢复默认修正"一键清空全部自定义;
- 每次操作都有 toast 明确提示**是否成功持久化**。

### 持久化

- 优先使用 `localStorage` 保存用户改动(保存的是与 `config.js` 默认值的**差量**),
  下次打开自动回放;
- 启动时探测 `localStorage` 可用性;不可用(如部分 `file://` 严格模式)时自动降级为
  **仅本次会话有效**,并在面板中明示,长期维护请编辑 `config.js`;
- 持久化失败**绝不影响**时钟与峰谷计算。

### 编辑 config.js(长期维护)

```js
// 法定节假日(放假的日期;调休上班日不要收录)
holidays: ['2026-01-01', ...],

// 默认手动修正
dateOverrides: [{ date: '2027-01-01', type: 'holiday' }],

// 数据覆盖范围提示
holidayDataCoverage: { from: '2026-01-01', to: '2026-12-31' }
```

> 内置的 2026 年节假日为**人工整理**(依据国办发明电〔2025〕7 号);
> 每年国务院新通知发布后请按[规则维护指南](#规则维护指南)更新。
> 未收录的年份不会被自动识别,请用界面手动修正。

## 技术架构

- **经典脚本,无模块系统**:按 `config.js → schedule.js → app.js` 顺序通过
  `<script src>` 加载,共享全局命名空间 `window.DTW`(`DTW.config` / `DTW.schedule`),
  避免 `file://` 下 ES Module 的兼容问题。`config.js` 与 `schedule.js` 同时兼容
  浏览器与 Node(用于命令行冒烟测试)。
- **无外部运行时依赖**:不使用 React/Vue、npm、Webpack、CDN、在线字体、第三方库。
- **时间处理**:
  - `Intl.DateTimeFormat('en-GB', { timeZone, hourCycle: 'h23' }).formatToParts()`
    获取任一时区的年月日时分秒(午夜小时恒为 00);
  - `zonedTimeToUtc(wall, tz)` 迭代校正法把"某时区墙钟时间"转为真实时间戳,
    自动处理夏令时偏移,对非法日期、无效时区、夏令时跳空时刻抛出明确错误;
  - 星期与日期加减使用纯 UTC 日期运算,与系统时区无关。
- **性能**:250ms 轻量 tick 仅更新时钟/倒计时文字与标记角度;圆环弧线只在日期或
  规则变化时重绘;SVG 节点在启动时一次性构建。
- **视觉**:深蓝夜空渐变背景 + 白色圆角卡片 + 蓝色高亮;`prefers-reduced-motion`
  下关闭全部动画;`[hidden] { display: none !important }` 全局守卫确保隐藏属性
  不被组件 display 规则覆盖(此为一次真实 bug 的修复沉淀)。
- **设置二级页**:角色卡片即按钮(`<button>` + `aria-haspopup="dialog"`),点击后
  居中悬浮面板展示时区与计费规则卡片,`backdrop-filter: blur(10px)` 模糊背景;
  支持 ✕、点击遮罩、Esc 逐层关闭;节假日管理面板层级更高(z-index 50)。

## schedule.js API 参考

全部挂载在 `DTW.schedule` 下。

### 常量

| 名称 | 值 | 说明 |
|---|---|---|
| `BILLING_TZ` | `'Asia/Shanghai'` | 计费判断基准时区 |
| `MINUTES_PER_DAY` | `1440` | 全天分钟数 |
| `WEEKDAYS_CN` | `['日','一',…,'六']` | 星期文案 |

### 时区与日期工具

| 函数 | 说明 |
|---|---|
| `getZonedParts(timestamp, tz)` | 时间戳 → 指定时区墙钟 `{year,month,day,hour,minute,second}`;无效时区抛错 |
| `zonedTimeToUtc(wall, tz)` | 指定时区墙钟 → 真实时间戳(迭代校正);非法输入/跳空时刻抛错 |
| `dateKeyOf(y, m, d)` | → `'YYYY-MM-DD'` |
| `isValidDateString(str)` | 严格校验 `YYYY-MM-DD` 且为真实公历日期 |
| `weekdayOfDate(dateStr)` | → 0(周日)… 6(周六),纯 UTC 运算 |
| `addDays(dateStr, n)` | 日期键 ±n 天(可跨月跨年) |
| `pad2(n)` | 两位补零 |

### 规则数据与手动修正

| 函数 | 说明 |
|---|---|
| `getPeakPeriods()` | 当前峰时区间副本 `[{start,end}]`(分钟,左闭右开) |
| `getAutoHolidays()` | config 中的法定节假日列表副本 |
| `setOverride(dateStr, 'holiday'\|'normal')` | 新增/修改手动修正;非法输入抛错 |
| `removeOverride(dateStr)` | 删除某日修正,恢复自动判断 |
| `resetOverrides()` | 恢复为 config 默认修正(测试与"恢复默认"使用) |
| `getEffectiveOverrides()` | 当前生效修正表副本 |
| `getUserDeltas()` | 与 config 默认值的差量(供持久化) |
| `applyUserDeltas(deltas)` | 启动时回放持久化的改动(非法条目静默忽略) |

### 核心计算

| 函数 | 说明 |
|---|---|
| `resolveDateType(dateStr)` | → `{type: 'workday'\|'weekend'\|'holiday', source}` |
| `getDaySegments(dateStr)` | 当天完整峰谷区间(无重叠无遗漏,合计 1440 分钟) |
| `getStateAt(timestamp)` | 某真实时刻的状态:`{state, dateStr, minuteOfDay, secondOfDay, dayType, daySource, beijing}` |
| `getNextSwitch(timestamp)` | 下一次状态切换:`{timestamp, fromState, toState, beijing}`(逐日扫描,默认上限 31 天) |
| `getCountdownTo(timestamp, targetTs)` | 倒计时拆分 `{totalSeconds, days, hours, minutes, seconds}`(向上取整,不为负) |

### 圆环几何

| 函数 | 说明 |
|---|---|
| `minuteToAngle(min)` | 当天分钟数 → SVG 角度(00:00 = -90° 正上方,顺时针) |
| `polarToCartesian(cx, cy, r, deg)` | 极坐标 → SVG 直角坐标(y 轴向下) |

## 规则维护指南

DeepSeek 可能调整计费规则;节假日每年由国务院发布新安排。维护时**只改 `config.js`,
不需要动计算逻辑**:

1. **峰谷时段调整** → 修改 `peakPeriods`(单位:当天分钟数,左闭右开):

   ```js
   peakPeriods: [
     { start: 9 * 60, end: 12 * 60 },   // 09:00 - 12:00
     { start: 14 * 60, end: 18 * 60 }   // 14:00 - 18:00
   ]
   ```

   区间可增删,圆环、状态、倒计时会自动按新区间工作(非法或重叠区间会在控制台告警并兜底)。

2. **新一年节假日** → 把放假的日期追加到 `holidays`(只收放假日期,不调休上班日),
   并更新 `holidayDataCoverage`。
3. **核对官方规则后** → 更新 `meta.ruleVersion` 与 `meta.lastVerified`。
4. **改完务必**:打开 `tests.html` 全量回归 + 用浏览器实际打开 `index.html` 抽查
   工作日/周末/节假日三天。

## 浏览器兼容性

| 能力 | 要求 |
|---|---|
| 时区处理 | `Intl.DateTimeFormat` + `formatToParts` + IANA timeZone(Chrome 57+ / Firefox 51+ / Safari 11+) |
| 背景模糊 | `backdrop-filter`(不支持时退化为半透明压暗,不影响功能) |
| 本地存储 | `localStorage`(不可用时自动降级为会话内有效,有明示) |
| 其他 | 不使用 ES Module、可选链等新语法,经典 ES5+ 语法为主 |

已过时的浏览器(无 `Intl` 时区支持)会在页面顶部显示错误横幅,其余功能尽量继续。

## 异常处理清单

| 场景 | 行为 |
|---|---|
| `pic.jpg` 缺失或加载失败 | 显示友好占位(鲸鱼图标 + 提示),不影响其他功能;图片恢复后自动回显 |
| `localStorage` 不可用 | 修改仅本次会话有效并明确提示;主功能不受影响 |
| 手动日期格式错误/不存在(如 2026-02-30) | 表单内联报错,拒绝写入 |
| 系统本地时区获取失败 | "本地时间"按钮禁用并说明;保持北京时间 |
| 页面跨越午夜 | 自动检测北京日期变化,重绘圆环并重算切换点 |
| 浏览器从后台恢复 | `visibilitychange` 时立即全量重算时钟/状态/倒计时 |
| 节假日列表为空 | 只按星期与时段判断,面板提示手动添加 |
| 峰时区间配置非法/重叠 | 控制台告警并兜底(忽略非法项/截断),页面不崩溃 |
| 夏令时跳空时刻转换 | 抛出明确错误而不是静默给错时间 |

## 已知限制

- **法定节假日为人工整理清单**(当前覆盖 2026 全年),不联网自动识别;未收录年份
  需手动添加修正或更新 `config.js`。2026 年清单依据国办发明电〔2025〕7 号整理,
  未能在线二次复核,请以国务院最新通知为准（节假日通常变化不大，直接手动调整也很快）。
- 谷时 50% 价格等信息仅作界面提示,以官方最新定价页为准。
- 无头浏览器无法模拟鼠标悬停,hover 提示气泡只做了 CSS 规则验证,未做自动化视觉验证。
- 超窄窗口(≤ 500px)布局以无头浏览器最小窗口宽度验证,未在真实手机设备上测试。
- 设置面板打开时不做焦点陷阱(focus trap),仅提供 Esc/遮罩/按钮关闭。
